一、什么是功能测试
核心：验证软件业务功能是否符合需求文档，只关心 “能不能用、逻辑对不对”，不关心快不快、好不好看、安不安全。
模拟真实用户操作，校验页面、接口、业务流程的逻辑正确性，是所有测试里最基础、占比最高的测试类型。
二、功能测试三大流程分类
主流程
用户最常用、标准完整链路。
例：登录→选购商品→下单→支付→收货。
数据要素：
- 输入数据
- 输出数据
- 状态码
- 计算结果
- 异常处理


分支流程
主线衍生出的不同分支场景，不同条件对应不同结果。




例：下单后取消、超时未支付、退货退款。
反向 / 异常流程（反向操作）
不按正常逻辑操作，校验系统拦截能力。
例：跳过页面、颠倒操作顺序、重复提交、已完成单据再修改。
三、功能测试全覆盖测试点
1. 页面基础操作
新增、查询、编辑、删除、批量操作、导入、导出、复制、打印、筛选、排序、分页、重置。
2. 表单输入校验
必填项空值提交拦截
长度限制：最大 / 最小字符
格式校验：手机号、身份证、邮箱、数字、日期
边界值：0、最大值、负数、特殊符号、空格
重复数据、唯一性校验
3. 业务流程校验
完整主线、所有分支场景全覆盖
单据状态流转正常：草稿→待审核→通过 / 驳回→作废
操作顺序限制，逆向状态变更拦截
弹窗、提示、跳转、返回、刷新逻辑
4. 权限功能测试
不同角色（管理员 / 普通用户 / 访客）：
菜单是否可见
按钮能否点击
数据是否隔离（不能看到别人的数据）
越权操作拦截
5. 数据一致性
新增 / 修改 / 删除后数据库数据同步正确
关联数据联动更新（修改主表，附表同步变化）
操作失败不产生脏数据，事务可回滚
6. 第三方对接功能
短信、验证码、支付、文件上传、单点登录、外部系统数据同步。
7. 异常容错场景
断网提交、中途刷新页面、重复点击按钮、超大文件上传、空列表操作。
四、功能测试常用方法
等价类划分：把相同逻辑输入归为一类，每条类测一次
边界值分析：重点测临界数字、字符长度
场景法：覆盖主流程 + 所有分支流程（业务测试最常用）
错误推测法：反向操作、模拟用户乱点找 bug
五、举个简单实例：后台用户管理功能测试范围
正向：正常新增用户、编辑、删除、查询、分页
输入校验：用户名必填、手机号格式、密码长度限制
分支：启用用户 / 禁用用户两种状态，禁用后无法登录
反向：重复创建同名用户、不填必填项提交、批量删除后刷新列表
权限：普通员工看不到删除按钮，管理员可全部操作
六、和其他测试简单区分
功能测试：逻辑对不对（核心）
性能测试：系统快不快、扛不扛并发
兼容性：不同浏览器 / 手机能不能正常用
安全测试：会不会泄露数据、被攻击
UI 测试：页面排版、美观度

## 通用

- 测试页面必须包含必要的页面标题检查
 - 测试页面必须包含必要的页面描述检查
 - 测试页面必须包含必要的页面关键词检查
 - 测试页面必须包含必要的页面内容检查

## 页面访问规则

- 对于同一个页面的测试，每个用例测试完成后回到该页面，确保页面状态为初始状态，不用每个用例都登录一次
 - 测试页面必须包含必要的页面内容字段检查
 - 测试页面必须包含必要的页面字段输入元素框的检查

接口测试完整讲解
一、什么是接口测试
接口是系统之间、前后端之间数据交互通道（API），接口测试就是不依赖前端页面，直接调用服务接口，校验入参、逻辑、返回数据、异常拦截是否符合需求。
不用操作页面，用 Postman、Apifox、JMeter 等工具直接发请求，是测试里性价比很高的一环。
二、接口测试核心范围
1. 正向场景（正常参数）
传入合法完整参数，校验接口返回成功
返回状态码、返回字段、字段类型、数值与需求一致
分页、排序、筛选、关联数据正确
新增 / 修改 / 删除后数据库数据同步
2. 参数校验（重点）
必填参数不传、传空字符串
参数边界值：长度上限 / 下限、最大最小值
非法参数：特殊字符、中文、负数、超长文本
参数类型错误：数字传字符串、数组传对象
多余参数、缺失非必填参数
枚举参数：传不在枚举范围内的值
3. 权限与身份校验
无 token / 过期 token 调用接口，需拦截返回未登录
普通用户调用管理员专属接口，越权拦截
不同角色数据隔离，不能查询他人数据
签名、加密、验证码校验失效场景
4. 业务逻辑分支
和功能测试分支流程对应，所有业务分支单独调用接口验证：
订单：待支付 / 已支付 / 已取消 / 已退款 各状态接口
审批：提交、撤回、通过、驳回接口分别校验
5. 异常 & 反向场景
重复提交同一请求（幂等性测试，不能生成多条脏数据）
并发调用同一修改 / 删除接口
操作已删除、已作废的数据
传递不存在 ID（不存在用户 ID、订单 ID）
上传超大文件、非法格式文件接口
网络超时、服务异常重试逻辑
6. 数据一致性
接口操作后数据库新增、更新、删除数据准确
多表关联数据同步，无脏数据、无冗余数据
事务失败时数据回滚，不会半更新
7. 第三方接口联调
支付、短信、推送、外部系统同步接口：
正常回调、异常回调、重复回调处理
第三方返回异常值时自身系统容错
三、接口测试和功能测试区别
功能测试：从页面操作，用户视角，侧重流程；页面有前端二次校验，部分后端漏洞测不到
接口测试：直接访问后端逻辑，绕过前端限制，更容易发现越权、参数绕过、数据脏数据问题
举例：
前端页面限制数字输入，但接口直接传字母，前端拦不住，只能接口测试发现漏洞。
四、常用测试方法
等价类划分：合法 / 非法参数分类覆盖
边界值：数值、字符长度临界值
场景法：完整业务链路接口串联（登录→创建→查询→修改→删除）
错误推测：异常参数、越权、重复请求
五、简单例子（用户新增接口）
正向：传正确用户名、手机号、角色，返回创建成功，库中有数据
参数异常：手机号格式错误、用户名为空、长度超 50 字符，返回明确错误提示
反向：传已存在用户名，提示重复；传不存在角色 ID，报错拦截
权限：游客不带 token 调用，返回 401 未授权
幂等：连续调用 2 次新增，不会生成两条相同用户
